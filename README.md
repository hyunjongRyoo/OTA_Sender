# OTA Sender v2.0.1

Windows PC에서 SoC의 APP 펌웨어 BIN 파일을 TCP로 전송하는 OTA 도구입니다.

GUI는 PC에서 TCP 서버를 열고 접속한 여러 SoC를 IP 목록으로 표시한 뒤, 선택한 기기에 기존 OTA 프로토콜로 순차 전송합니다.

## Windows 배포본 다운로드

[v2.0.1 릴리스](https://github.com/hyunjongRyoo/OTA_Sender/releases/tag/v2.0.1)에서
`OTA_Sender_v2.0.1.zip`을 내려받아 압축을 풀고 `OTA_Sender.exe`를 실행합니다.
배포본은 Python 설치 없이 실행할 수 있으며 ZIP에는 실행 파일과 이 README가 포함됩니다.
업데이트할 APP 펌웨어 `.bin` 파일은 별도로 준비합니다.

기존 사용자는 프로그램을 종료한 뒤 EXE를 교체합니다. 마지막 성공 일자를 유지하려면
같은 폴더의 `update_history.json`을 보존하세요. 배포 ZIP에는 개인 장비 이력을 포함하지 않습니다.

## v2.0.1 변경 내용

- 장비 목록 확대, 체크박스 확대, 전체 선택과 부분 선택 표시
- 열별 오름차순/내림차순 정렬 및 시작 시 화면 순서에 따른 업데이트
- 접이식 로그와 진행/TX/RX 탭, 목록과 로그 높이 조절
- 미완료 장비의 노란색 강조와 성공/실패/진행/대기 집계, 실패 장비 번호 표시
- IP별 마지막 전송 성공 일자 저장 및 재실행 시 복원
- 1회 재시도 후 실패해도 다음 장비 계속 처리, 미완료 장비만 재선택
- 전송 성공 후 실제 버전 자동 재조회, 전송 결과와 조회 결과 구분

회귀 테스트 17개와 Windows EXE 빌드를 확인했습니다. 실장비 OTA 전송은 별도 현장 검증이 필요합니다.

## 현재 기능

- 로컬 PC IPv4 주소 선택 및 새로 고침
- TCP 서버에 접속한 SoC IP와 포트 표시
- TCP 연결 직후 `VER?`를 전송하여 TTL 아래 열화상 MCU의 현재 FW 버전 표시
- 연결 후 1초 대기, 최대 10초 응답 대기 및 실패 시 1회 재조회
- 여러 장비의 버전은 한 대씩 순차 조회
- `Refresh List`로 현재 연결된 전체 장비의 버전 다시 조회
- 동일 IP 재접속 시 기존 행을 최신 연결로 갱신
- 큰 체크박스와 헤더 전체 선택/해제, 부분 선택 표시 (현재 연결되어 조회를 마친 장비 대상)
- IP, 포트, 현재 버전, 상태, 마지막 성공 일시 헤더 클릭으로 오름차순/내림차순 정렬
- IP와 숫자 버전은 숫자 기준 정렬, 버전 미확인은 `-` 표시
- 업데이트 시작 시 화면에 정렬된 순서대로 체크된 장비만 전송
- 목록 중심의 확장 가능한 화면, 하단 접이식 로그 및 진행/TX/RX 탭
- 실행 중 기기별 OTA 상태와 마지막 성공 일시 표시 및 IP별 파일 저장
- 이번 작업 대상 중 아직 성공하지 않은 장비는 형광 노란색 행으로 강조
- 성공/실패/진행/대기 집계와 실패 장비 번호(IP 마지막 숫자)를 목록 위에 표시
- APP 펌웨어 `.bin` 파일 선택
- 펌웨어 크기 및 CRC32 전송
- 청크 단위 펌웨어 전송과 진행률 표시
- TX/RX 데이터와 OTA 진행 로그 표시

현재 버전은 여러 SoC 연결을 IP별 목록으로 표시하고 선택한 기기를 순차 업데이트합니다.
기기 OTA가 실패하면 5초 대기 후 해당 기기에 한 번 다시 전송합니다. 재시도도
실패하면 해당 기기를 OTA 실패로 표시하고 다음 기기의 업데이트를 계속 진행합니다.

## OTA 순서

프로그램은 다음 순서로 기존 OTA 명령을 전송합니다.

1. `FWU!` 전송 후 `FWU=READ` 확인
2. `FWH!`로 파일 크기와 CRC32 전송 후 `FWH=READ` 확인
3. `FWD!`로 BIN 데이터를 청크 단위 전송
4. 중간 청크의 `FWD=READ` 및 마지막 청크의 `FWD=SUCC` 확인

헤더의 파일 크기와 CRC32는 little-endian 32비트 값으로 전송합니다. 데이터 청크 크기는 244바이트입니다.

## 소스 실행 방법 및 사용 순서

Python 3가 설치된 Windows PC에서 다음 명령으로 GUI를 실행합니다.

```powershell
python ota_send_gui.py
```

사용 순서:

1. `Local PC IP`에서 SoC가 접속할 서버 PC 주소를 선택합니다.
2. 포트를 확인합니다. 기본값은 TCP `9001`입니다.
3. `Start Server`를 누른 뒤 접속한 SoC의 현재 버전을 확인하고 업데이트할 기기를 선택합니다.
4. APP 펌웨어 BIN 파일을 선택합니다.
5. 원하는 열을 클릭해 정렬한 뒤 `Start Update`를 누릅니다. 화면 순서대로 선택된 기기를 업데이트합니다.
6. 진행 로그에서 `FWD=SUCC`와 완료 메시지를 확인합니다.

기기별 첫 OTA가 실패하면 5초 후 한 번 다시 전송합니다. 재시도도
실패하면 해당 기기를 `OTA Failed`로 표시하고 다음 기기의 업데이트를 계속 진행합니다.
마지막 성공 일시는 `send_ota`가 정상 완료된 시점의 PC 로컬 시각입니다.
정상 BIN 전송의 마지막 `FWD=SUCC` 확인이라는 기존 성공 판정을 유지하며,
재부팅 후 목표 버전 일치까지 확인했다는 뜻은 아닙니다.
전송 성공 후 이전 버전 표시는 `-`로 지우고 문서상 MCU 재부팅 대기 시간인 3초 이후
기존 버전 조회를 시작합니다(기존 조회의 요청 전 1초 대기 및 1회 재시도 유지).
같은 TCP 연결이 유지되어도 자동 조회하며, 재접속 시에도 버전을 다시 조회합니다.
상태는 `전송 성공 / 버전 조회 대기·조회 중·조회 완료·확인 불가`로 구분합니다.
조회 실패는 전송 실패로 집계하지 않으며 `Refresh List`로 다시 조회할 수 있습니다.
표시된 버전은 실제 `VER=` 응답값입니다. 목표 버전 입력이나 BIN 버전 추정·일치 판정은 하지 않습니다.
이전 연결 또는 이전 조회의 늦은 결과는 새 조회 결과를 덮어쓰지 않습니다.
GUI 스크립트(또는 EXE) 옆 `update_history.json`에 IP별로 저장하고 다음 실행 및 접속 시 복원합니다.
실패한 시도는 마지막 성공 일시를 덮어쓰지 않습니다. 다른 PC에서 수행한 이력은 알 수 없으며,
장비 IP가 바뀌면 기존 이력이 자동으로 따라가지 않습니다. 저장 실패 시 오류를 표시합니다.

업데이트 중 정렬과 선택을 잠가 시작 시의 실행 순서를 유지합니다.
현재 작업 대상 중 대기·진행·재시도·실패 장비를 노란색으로 표시하며,
실패는 빨간 글씨, 성공은 옅은 녹색으로 구분합니다. 목표 BIN 버전을 추정하거나 비교하지 않습니다.
재접속·버전 재조회 후에도 이번 작업 결과와 강조를 유지합니다.
재시도까지 실패한 장비는 실패로 남기고 다음 장비를 계속 처리합니다.
처리가 끝난 뒤 `미완료 장비만 선택`을 누르면 마지막 작업에서 성공하지 않은 장비 중
현재 연결되어 조회를 마친 장비만 체크됩니다. 성공 장비와 마지막 작업 대상이 아닌 장비는
체크가 해제됩니다. 연결이 끊긴 장비는 재접속·조회 완료 후 버튼을 다시 누릅니다.
이 버튼은 선택만 변경하며 전송은 `Start Update`를 눌러 시작합니다.
실패 번호는 IP 마지막 숫자이며 전체 IP는 같은 행의 Device IP 열에서 확인합니다.
상단 집계는 마지막으로 시작한 작업 기준이고 새 작업을 시작하면 초기화됩니다.
로그는 기본적으로 접혀 있으며 `로그 펼치기`를 누르면 탭으로 확인할 수 있습니다.
펼친 로그와 목록 사이 경계선을 드래그하면 높이를 조절할 수 있습니다.
버전 조회가 실패해도 TCP 연결과 OTA 기능은 유지하며 현재 버전은 `-`로 표시합니다.
버전 조회는 연결 후 1초 뒤 시작하고 10초 안에 응답이 없으면 1초 뒤 한 번
재시도합니다. 여러 장비는 한 대씩 순차 조회하며, `Refresh List`를 누르면 현재
연결된 장비에 같은 조회 절차를 다시 수행합니다.

## CLI 실행

```powershell
python ota_send.py firmware.bin --host 0.0.0.0 --port 9001
```

## Windows EXE 빌드

PyInstaller 설치 후 저장소 루트에서 빌드합니다.

```powershell
python -m pip install pyinstaller
pyinstaller --clean ota_send_gui.spec
pyinstaller --clean ota_send.spec
```

생성 파일:

- GUI: `dist/ota_send_gui.exe`
- CLI: `dist/ota_send.exe`

현장 배포본에서는 GUI 실행 파일을 `OTA_Sender.exe`라는 이름으로 사용합니다.

## 파일 구성

- `ota_send_gui.py`: Windows GUI 및 다중 TCP OTA 연결 관리
- `ota_send.py`: OTA 프레임 처리와 BIN 전송 로직, CLI
- `ota_send_gui.spec`: GUI용 PyInstaller 빌드 설정
- `ota_send.spec`: CLI용 PyInstaller 빌드 설정
- `test_ota_send_gui.py`: 실제 Tk 위젯 기반 회귀 테스트 (실장비 전송 없음)

## 검증

```powershell
python -m unittest -v test_ota_send_gui
```

숫자 정렬, 전체/부분 선택, 화면 순서의 실행, 실패 시 재시도 후 다음 장비 계속 처리, 미완료 선택,
연결 해제 후 결과 집계, 재접속 시 결과 유지, 성공 일자 저장·복원, 로그 접기를 확인합니다.

## 현재 버전 범위

- 다중 기기 목록, 대상 선택 및 선택 기기 순차 업데이트 지원
- PC TCP 서버 기본 포트는 9001 사용
- 실패 시 5초 대기 후 1회 재시도, 재시도 실패 시 다음 장비 계속 처리
- OTA 명령, 패킷 형식, CRC32 및 청크 크기는 현재 현장용 구현을 유지
